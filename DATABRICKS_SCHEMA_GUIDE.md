# Databricks Lakehouse Schema & Ingestion Guide

This guide provides the exact step-by-step instructions and SQL statements to configure your **Databricks Catalog, Dual-Schema Architecture (`gold` & `app`)**, create all Delta tables, and load the 3 benchmark datasets using `COPY INTO`.

---

## 🏗️ Architecture Overview

| Schema | Role | Tables |
| :--- | :--- | :--- |
| **`gold`** | **Analytical / Benchmark Data** (Read-Only) | `bass_features`, `weekly_rx`, `analog_features` |
| **`app`** | **Operational / Application Data** (Transactional) | `organizations`, `users`, `analog_products`, `user_forecast_inputs`, `forecast_records`, `actual_launch_rx` |

---

## 📋 Step 1: Create Catalog and Schemas

Run the following in **Databricks SQL Editor** or in a **Databricks Notebook**:

```sql
CREATE CATALOG IF NOT EXISTS drug_forecasting;
USE CATALOG drug_forecasting;

CREATE SCHEMA IF NOT EXISTS gold;
CREATE SCHEMA IF NOT EXISTS app;
```

## 📥 Step 3: Ingest the 3 CSV Files via `COPY INTO`

### Option A: Using Databricks Unity Catalog Volume (Recommended)
1. In Databricks Workspace, go to **Catalog → `drug_forecasting` → `gold` → Create Volume** named `data`.
2. Click **Upload to Volume** and upload the 3 CSV files from `data/`:
   - `bass_final.csv`
   - `weekly_rx_final.csv`
   - `similarity+analog_features_final.csv`
3. Execute the following `COPY INTO` commands in SQL Editor:

```sql
-- 1. Ingest Bass Features
COPY INTO drug_forecasting.gold.bass_features
FROM '/Volumes/drug_forecasting/gold/data/bass_final.csv'
FILEFORMAT = CSV
FORMAT_OPTIONS (
    'header' = 'true',
    'inferSchema' = 'true',
    'mergeSchema' = 'true'
)
COPY_OPTIONS ('mergeSchema' = 'true');

-- 2. Ingest Weekly Rx Adoption Trajectories
COPY INTO drug_forecasting.gold.weekly_rx
FROM '/Volumes/drug_forecasting/gold/data/weekly_rx_final.csv'
FILEFORMAT = CSV
FORMAT_OPTIONS (
    'header' = 'true',
    'inferSchema' = 'true',
    'mergeSchema' = 'true'
)
COPY_OPTIONS ('mergeSchema' = 'true');

-- 3. Ingest Analog Clinical & Commercial Features
COPY INTO drug_forecasting.gold.analog_features
FROM '/Volumes/drug_forecasting/gold/data/similarity+analog_features_final.csv'
FILEFORMAT = CSV
FORMAT_OPTIONS (
    'header' = 'true',
    'inferSchema' = 'true',
    'mergeSchema' = 'true'
)
COPY_OPTIONS ('mergeSchema' = 'true');
```

### Option B: Ingest Directly from AWS S3 Bucket
If your files are uploaded to your AWS S3 bucket (`s3://forecast-drug-data-bucket/`):

```sql
-- 1. Ingest Bass Features from S3
COPY INTO drug_forecasting.gold.bass_features
FROM 's3://forecast-drug-data-bucket/bass_final.csv'
FILEFORMAT = CSV
FORMAT_OPTIONS ('header' = 'true');

-- 2. Ingest Weekly Rx from S3
COPY INTO drug_forecasting.gold.weekly_rx
FROM 's3://forecast-drug-data-bucket/weekly_rx_final.csv'
FILEFORMAT = CSV
FORMAT_OPTIONS ('header' = 'true');

-- 3. Ingest Analog Features from S3
COPY INTO drug_forecasting.gold.analog_features
FROM 's3://forecast-drug-data-bucket/similarity+analog_features_final.csv'
FILEFORMAT = CSV
FORMAT_OPTIONS ('header' = 'true');
```

## 📱 Step 4: Create `app` Schema Tables (Application Data)

```sql
USE SCHEMA app;

-- 1. Organizations Table
CREATE TABLE IF NOT EXISTS drug_forecasting.app.organizations (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name STRING NOT NULL,
    created_at TIMESTAMP
);

-- 2. Users Table
CREATE TABLE IF NOT EXISTS drug_forecasting.app.users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email STRING NOT NULL,
    hashed_password STRING NOT NULL,
    full_name STRING,
    role STRING NOT NULL,
    organization_id BIGINT,
    created_at TIMESTAMP
);

-- 3. Analog Catalog Table (App Schema)
CREATE TABLE IF NOT EXISTS drug_forecasting.app.analog_products (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    product_id STRING NOT NULL,
    therapeutic_area STRING NOT NULL,
    indication STRING NOT NULL,
    active_ingredient STRING,
    pharmacological_class STRING,
    mechanism_of_action STRING,
    route_of_administration STRING,
    target_population STRING,
    addressable_population DOUBLE,
    competition_level DOUBLE,
    relative_price_index DOUBLE,
    market_access_level DOUBLE,
    clinical_evidence_strength DOUBLE,
    created_at TIMESTAMP
);

-- 4. User Forecast Inputs Table
CREATE TABLE IF NOT EXISTS drug_forecasting.app.user_forecast_inputs (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT,
    product_id STRING,
    product_name STRING,
    therapeutic_area STRING,
    indication STRING,
    addressable_population DOUBLE,
    estimated_penetration DOUBLE,
    top_k INT,
    w_analog DOUBLE,
    user_inputs_json STRING,
    created_at TIMESTAMP
);

-- 5. Forecast Calculation Records Table
CREATE TABLE IF NOT EXISTS drug_forecasting.app.forecast_records (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    organization_id BIGINT,
    user_id BIGINT,
    product_id STRING,
    product_name STRING,
    therapeutic_area STRING,
    indication STRING,
    addressable_population DOUBLE,
    estimated_penetration DOUBLE,
    p_hat DOUBLE,
    q_hat DOUBLE,
    m_hat DOUBLE,
    base_52w_rx DOUBLE,
    bull_52w_rx DOUBLE,
    bear_52w_rx DOUBLE,
    top_k INT,
    w_analog DOUBLE,
    input_json STRING,
    bass_params_json STRING,
    analogs_used_json STRING,
    weekly_forecast_json STRING,
    monthly_forecast_json STRING,
    explanations_json STRING,
    created_at TIMESTAMP
);

-- 6. Actual Post-Launch Rx Comparison Table (Optional Tracking)
CREATE TABLE IF NOT EXISTS drug_forecasting.app.actual_launch_rx (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    product_id STRING NOT NULL,
    week_since_launch INT NOT NULL,
    actual_weekly_rx DOUBLE NOT NULL,
    actual_cumulative_rx DOUBLE NOT NULL,
    recorded_at TIMESTAMP
);
```

## 🔍 Step 5: Verification Queries

After running the DDL and `COPY INTO` commands, run these verification queries:

```sql
-- Check row counts in Gold tables
SELECT 'gold.bass_features' AS table_name, count(*) AS total_rows FROM drug_forecasting.gold.bass_features
UNION ALL
SELECT 'gold.weekly_rx' AS table_name, count(*) AS total_rows FROM drug_forecasting.gold.weekly_rx
UNION ALL
SELECT 'gold.analog_features' AS table_name, count(*) AS total_rows FROM drug_forecasting.gold.analog_features;

-- Expected Output:
-- gold.bass_features:   150 rows
-- gold.weekly_rx:       7800 rows (150 products × 52 weeks)
-- gold.analog_features: 150 rows
```
